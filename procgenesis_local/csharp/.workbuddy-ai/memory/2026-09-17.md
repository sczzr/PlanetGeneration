# 2026-09-17

## 多边形地块改造方案（设计，未改代码）

产出 `docs/多边形地块改造方案.md`：参考 Azgaar/Fantasy-Map-Generator 的 Voronoi 地块方案，为本项目（PlanetGeneration, Godot 4.7.2 mono/C#）设计"栅格 → 多边形地块"改造。

**关键结论与事实（后续会话可直接复用）**

- 本项目**没有地块实体**：地块 = 栅格单元。`WorldGen/Types.cs` 只有枚举/结果容器；14 个生成器签名均为 `(int width, int height, ... float[,])`；`WorldRenderer.Render` 逐像素写 RGBA buffer；拾取 `sampleX = (int)(tX * MapWidth)`。
- **经度方向环绕**（`WrapX`），y 方向钳制 → 等距圆柱投影、经度 360° 首尾相接。这是与 FMG（平面图 + 边界伪点）最大的差异，多边形网格必须做**镜像点**，否则跨缝地块断裂。
- 推荐路线：**混合模式**——保留全部生成器算法（场层），新增 Voronoi 地块层作为属性真源，栅格降级为投影。新增 8 个文件（`scripts/WorldGen/Polygon/`），修改 9 个，不动生成器/小地图/图例/LLM/UI。
- 兼容三机制：`PolygonTileMode{Raster,Hybrid,PolygonOnly}` 开关、`RasterPolygonBridge`（SampleFromRaster / SplatToRaster）、`WorldGenerationAlgorithmVersion` 3 → 4。
- 缓存只存 `Points + Boundary`，加载时重建拓扑（FMG `rebuildGraph` 思路），约 8 字节/地块。

## 多边形地块 P0（几何核心）已实施并自检通过

新增 8 个文件（约 2400 行）于 `scripts/WorldGen/Polygon/`，**未改动任何既有文件**，原有功能不受影响：
`PolyVec2` / `VoronoiBuilder` / `PolygonGrid` / `PolygonGridBuilder` / `PolygonFields` / `PolygonTopologyBuilder` / `PolygonGridValidator` / `PolygonTileMode`。
整个命名空间**不引用 Godot**，可脱离编辑器独立编译自检。

**关键设计决策（与初版方案的偏差，需记住理由）**

- **放弃 Bowyer–Watson Delaunay，改用「半平面裁剪 + 顶点校验」**。理由：C# 无现成 Delaunator；裁剪法的正确性可自证（每个角点都能验证"没有更近的点切掉它"），而 Delaunay 的邻接/退化 bug 只能靠肉眼比对。逐条裁剪按候选距离升序、以"二分面到站点距离 = 候选距离的一半 ≥ 当前多边形最大顶点半径"作为**精确**提前退出判据。
- 顶点存 `double`：顶点去重依赖两次独立裁剪得到同一坐标，float32 在 4096 量级只有约 0.04px 分辨力。
- 点距取整成能整除地图尺寸的值（`SpacingX × Columns == Width`），使点阵在经度方向**严格周期**，缝两侧点距与其他位置完全一致。
- 几何与邻接用 CSR 扁平存储；**未做全局顶点去重**（FMG 的 `vertices.p`），推迟到真正需要顶点级邻接时再加。

**实测（C#，32768 地块）**：建图 313~437 ms，131072 地块 1.3 s；面积覆盖率 **100.0000%**，平均邻接 5.97，补裁/退化/校验失败全 0；精确拾取与暴力最近点 200000/200000 一致。

**自检抓到的四个真问题（教训）**

1. **判据本身写错**：最初用"最左列与最右列必须互为邻居"当环绕判据 → 3 个地块不满足。真相是同列上下行站点抖动到最左会把中间地块夹住，它本就不该与最右列相邻（合法环面铺砌）。改用结构性判据：①每条非极边的归属必须在邻接表里 ②`顶点数 == 邻接数 + 极边数` ③无顶点落在包围盒经度边界上。
2. 周期小时（列数 ≤ 6）`MirroredPosition` 只取"最近的一个镜像副本"会漏约束（两个镜像可能等距）→ 必须枚举全部副本。
3. 裁剪会在近乎相切处留下**冗余共线顶点** → 顶点数虚高、拖慢光栅化、结构性判据失真 → 裁剪后统一清理（容差 1e-7px）。
4. **`SiteIndex.FindNearest` 返回平方距离而不是距离** → `ExtractNeighbors` 里"归属距离 > 自身距离"永远成立，邻接表全空；`FindViolator` 同理漏判。症状是"看起来一切正常，只有邻接表是空的"，只查面积/拾取根本发现不了。

**新增 1 个 Godot 侧文件**：`scripts/Main.Polygon.cs`（地块层的构建、懒加载、渲染、信息摘要）。
**修改 9 个既有文件**（全部接线级）：`WorldGen/WorldRenderer.cs`（MapLayer 追加 `PolygonGrid` + 3 个取色接口）、`Main.State.cs`（算法版本 3→4、地块层字段、`GeneratedWorldData` 扩展、`NaturalLayerIds`）、`Main.Generation.Driver.cs`（插 1 阶段，进度 10→11 步）、`Main.Rendering.cs`、`Main.Legend.cs`、`Main.Options.LayerMode.cs`、`Main.Export.cs`、`Main.Settings.cs`、`UI/State/GeneratorSettings.cs`。

**关键设计决策**

- **像素归属图（`PolygonCellMap`）是栅格与地块之间的唯一接缝**：采样与投影共用它，因此互为逆运算（`Sample(Splat(x)) == x` 逐位一致）。
- **地块层不进缓存**：它是 `(宽, 高, 种子, 目标地块数)` 的**纯函数**，属性又都从已缓存的栅格采样而来，缓存命中时按需重建（约 300ms）比序列化拓扑更划算。因此 `Main.Cache.Serialization.cs` 无需改动，只把算法版本升到 4 让旧缓存失效。
- 采样分三档：连续量**面积加权**、离散量**质心**、河流 **mean/max 混合**（河道只占少数像素，纯平均会被稀释到看不见）。
- 新增"地块划分"图层，复用生物群系配色 + 边界描边，用来和栅格版做 A/B 对照。
- 刻意**没加 UI 控件**：新图层走既有数据驱动图层列表，不需要改 `.tscn` 场景文件。

**实测**：归属图 512×256/8192 地块 9ms，零空洞；`Sample(Splat(x))` 8192/8192 逐位一致；光滑周期场投影平均误差 0.0026（理论上界 0.0179）；栅格群系 vs 地块群系仅 **1.42%**（8192 地块）/ 2.43%（2048 地块）像素不一致，且差异全在多边形边界。

**本轮抓到的两个问题（都是判据/测试场写错，不是实现错）**

1. 光滑场投影最大误差 0.478 远超上界 → **测试场在经度缝上不连续**（线性梯度从 1.0 跳到 0.0），跨缝地块覆盖整个值域。**跨缝测试必须用经度方向周期的场**。
2. "河流提升可见度"失败 → 只有约 1/3 地块真的含河道像素，其余三种算法都得 0。判据应只针对含河道的地块。

**新增基础设施（最重要）**

- `tools/godot-typecheck/GodotTypeCheck.csproj`：**Godot 工程的类型检查**。直接引用本地 NuGet 缓存里的 `GodotSharp.dll` 4.7.2 / `LLamaSharp.dll` 0.25.0 / `Microsoft.Extensions.Logging.Abstractions.dll` 9.0.8，编译 `csharp/scripts/**/*.cs`。基线 0 错误 / 45 个既有 nullable 警告。**改 Godot 侧代码前先跑它，否则等于盲改。**

## 多边形地块 P2（交互迁移 + 悬停高亮）已完成并验证

**新增 1 个 Godot 侧文件**：`scripts/MapCellOverlay.cs`（悬停高亮覆盖层）。
**核心层追加两个方法**：`PolygonGrid.GetHighlightRings`（高亮环几何）、`PolygonRasterizer.FillRing`（任意多边形填充）——放进核心层是为了能被自检覆盖。
**修改 3 个既有文件**：`Main.Lore.Interaction.cs`、`Main.Lore.Narrative.cs`、`Main.Oracle.cs`（另 `Main.Rendering.cs` 的城市列表追加地块编号，`Main.State.cs` 加 `CityCell`）。

**关键设计决策**

- **统一采样入口 `CellSample` + `TrySampleAtLocalPosition`**：把"鼠标落在哪里"统一成地块或像素两种来源，下游叙事/威胁评估/悬停面板/Oracle 只吃这个结构，因此 Raster 回退路径与地块路径**共用同一份展示逻辑**，不会出现"回退后文案不一样"的隐蔽分叉。
- **悬停高亮的跨经度缝处理**：顶点先平移到离质心最近的镜像副本，再按 `0 / ±Width` 各输出一份，超出的由带 `ClipContents` 的容器裁掉。**不需要在多边形层面做缝切分**——这是本轮最省事也最稳的一处设计。
- 覆盖层挂成 `MapTexture` 的子节点 → 局部坐标系就是纹理空间，与缩放的祖先（`MapAspect.Scale`）解耦，无需任何全局变换换算。
- **Oracle 自校验**：缓存的地块编号必须满足 `FindCell(锚点) == 缓存编号` 才使用，否则退回像素路径。这样重新生成世界后不需要到处埋重置逻辑。
- **地貌分类仍未地块化**（依赖 8 邻域像素统计），交互路径取地块质心所在像素以保持口径一致。改成用 `Cells.C` 真实邻接是 P4 的事。

**实测**：精确拾取与暴力最近点 200000/200000 一致；2048 个地块（43 个跨缝）的高亮环顶点数与面积全部一致、主环质心均在可见帧内、每个地块至少有一份副本落进画布；离线高亮预览确认左右与上下边缘的高亮都被正确裁剪。

**本轮抓到的问题**

1. 编译报"成员声明中的标记 } 无效"：替换方法时新块带上了类结束花括号，而原 `UpdateLoreFromMapSelection` 还在文件末尾 → 重复定义 + 花括号错位。**类型检查当场拦下**。

**无新增文件**；修改 5 个：`PolygonTileMode.cs`（枚举重定义）、`PolygonFields.cs`（加 `Landform`/`PlateBoundary`）、`WorldRenderer.cs`（加 3 个取色接口 + `DrawPlates` 改为复用 `GetPlateColor`）、`Main.Polygon.cs`、`Main.Rendering.cs`。

**关键设计决策**

- **模式枚举重定义**：`Raster`（全部栅格）/ `Hybrid`（离散图层多边形，默认）/ `Outlined`（+边界描边）。原 `PolygonOnly` 是个空壳，改名并赋予真实语义。
- **迁移判据是"离散分类 vs 连续场"**：离散量一个地块只有一种取值，多边形填充不在格子边界混色；连续场靠逐像素渐变/等值线表达信息，地块化会抹平。已迁移 `Biomes`/`RockTypes`/`Ores`/`Landform`/`Plates`。
- **两条路径共用同一套配色**：`WorldRenderer` 只开放取色函数，`DrawPlates` 与 `GetPlateColor` 共用实现 → 差异只可能来自几何，不可能来自调色（A/B 对照的前提）。
- **"地块划分"图层改为线框**（中性底色 + 边界）：它原来按群系着色，与"生物群系"图层完全重复。
- `BuildLayerRenderSignature` 必须把 `PolygonTileMode` 并进签名，否则切换模式后渲染缓存不失效。
- **增量重绘与 `PolygonPathBuilder` 都推迟到 P4**：前者前提是模拟地块化（现在拿不到"哪些地块变了"）；后者没有消费者（悬停高亮用 `GetHighlightRings` 够用，真正需要的是 P4 的河流折线与政体边界）。**先造没有消费者的抽象只会变成负担。**

**实测**：多边形渲染**填充全部忠实、无一个地块内部混色**；与栅格渲染差异 3.09%（全部来自分类块与地块的尺度差）；类型检查 0 错误 / 45 警告。

**本轮修正的判据错误（重要教训）**：最初想断言"差异像素必须全部位于地块边界"——错的。差异出现在**分类块边界**上（地块横跨两个分类块时只能取质心那一个），与地块边界无关。正确做法是判据落在**多边形渲染自己的定义性属性**（同一地块内像素颜色完全一致）上，而不是拿栅格渲染当基准。这与 P0 那次"环绕判据写错"是同一类错误：**判据必须能被证伪，且不能把另一个实现当真理。**

**P3 之后的图景**：剩下的 `Ecology`/`Civilization`/`TradeRoutes`/`Rivers`/`Cities` 留在栅格，原因不是渲染层做不到，而是**数据源还在逐像素的模拟器里**。P4 = 把模拟搬到地块上，渲染与增量重绘自然跟上。

**新增 2 个核心文件**：`PolygonLandformClassifier.cs`（地块邻接地貌分类）、`PolygonRiverBuilder.cs`（地块排水面积累积河网）。
**修改**：`PolygonTileMode.cs`（新增 `Cells` 档并设为默认）、`WorldRenderer.cs`（补 4 个取色接口 + `DrawSatellite` 重构成"极区掩膜作参数"）、`Main.Polygon.cs`（接入两者 + 扩展逐地块取色）、`Main.Rendering.cs`、`Main.State.cs`、`Main.Settings.cs`、`GeneratorSettings.cs`。

**目标状态已达成**：`PolygonTileMode.Cells` 为默认——**游戏地图就是多边形单元格**，所有能按地块属性着色的图层（地形总览/板块/温度/河流/湿度/高程/岩石/矿产/生物群系/地貌）都用多边形填充。剩下 `Ecology`/`Civilization`/`TradeRoutes`/`Cities`/`Wind` 留栅格（数据源仍是逐像素模拟器 / 需要箭头叠加）。

**关键设计决策**

- **地貌分类用 `Cells.C` 真实邻接**替代 8 邻域像素。唯一必要调整：邻接数不是固定 8（抖动方格下 5~7），所以"多少个邻居更高"改成按**比例**比较，否则地块因邻居少而永远达不到阈值。图层与悬停面板现在读同一份结果。
- **河流用排水面积累积**：降序遍历一次完成，无需迭代收敛。与栅格版（源头随机游走 + 8 方向择优）的根本区别是河道沿真实多边形邻接流动。
- **连续场取色复用**：`DrawSatellite` 重构成"极区掩膜作参数"，逐像素与逐地块共用实现；`WorldRenderer` 只开放取色函数。

**本轮最重要的教训（靠离线预览图发现的）**

第一版河流按**汇流量分位数**取阈值。自检**全绿**——河道不断裂、可达水体、占比正确——但预览图一眼看出：**河道全挤在海岸线上，不向内陆延伸**。原因是汇流量沿程单调递增，取分位数就等于取"离海最近的一批"。**"正确但不像河"这类问题，只有看图能发现。** 修法：阈值改按**排水面积**（有多少地块的水从这里流出）取分位数。

**第二件事**：合成地形若是**径向穹顶**（水从峰顶辐射流走），只会形成一圈小流域，怎么调阈值都出不来长河。自检与预览的合成地形都必须加多倍频噪声，否则测的是"永远长不出河"的地形，结论无意义。

**实测**：地貌海陆一致、11 类非退化、可复现；河流 31 个河道地块占陆地 **6.18%**（设定 6%）、无断裂、无悬空水系；类型检查 0 错误 / 45 警告。

**P4 剩余**：`EcologySimulator`（174 行）与 `CivilizationSimulator`（1137 行，含政体扩张/边界/贸易走廊/纪元回放）仍是逐像素。它们地块化后才能迁移 `Ecology`/`Civilization`/`TradeRoutes` 三个图层并解锁增量重绘。这是重写一套模拟，不是换循环。

## 多边形地块 P4 第二阶段（生态与文明模拟地块化）已完成并验证

**新增 2 个核心文件**：`PolygonEcologySimulator.cs`、`PolygonCivilizationSimulator.cs`（约 1000 行，Godot 无关）。
**修改**：`Main.State.cs`（加 `PolygonCivilization` + 签名）、`Main.Polygon.cs`（`EnsurePolygonCivilization`、`ShouldRenderAsPolygon` 排除表缩到只剩 `Wind`、两个取色分支）、`WorldRenderer.cs`（补 `GetCivilizationColor` / `GetTradeRouteColor`）、`Main.Rendering.cs`（信息栏分流）、`Main.Lore.Narrative.cs`（`PolygonCivilizationEvent` 重载）、`Main.Handlers.cs`（缓存失效补全）。
**新增自检**：`Program.RunEcologyCheck` / `RunCivilizationCheck`（共 15 条判据）；`PreviewRenderer.BuildCivilizationPreview`（第 6 个裸 RGBA 输出）；诊断入口 `PolygonSelfTest.dll diagciv`（`DiagCivilization.cs`）。

**三类必须改造而非机械平移的运算**（这是"难"的真正所在）

1. **邻域**：硬编码 8 邻域 → `grid.CellNeighbors` 真实邻接；"有几个外国邻居"改成按比例。
2. **扩张评分**：`sqrt(dx²+dy²)` → `grid.WrappedDistance`（测地距离）。
3. **贸易走廊**：像素直线光栅化（Bresenham 风格）→ 沿真实邻接的 Dijkstra 最短路（允许穿水，代价 ×6，保证岛屿间可通商且优先贴陆地）。

**量纲改造（唯一一处必须主动偏离栅格版）**：射程从**像素**改为**地块圈数 × spacing**。
`expansionRings = Lerp(3.5, 11, epochFactor) * Lerp(0.82, 1.2, diversityNorm)`。
理由：spacing 随地图尺寸与目标地块数在 4~16px 之间变化，同一个 `48` 在细图上覆盖 12 圈、粗图上只覆盖 3 圈——**同一套参数在不同地图上表现完全不同**。同样改造施于贸易射程、种子间距、走廊地形代价。
**踩坑两次**：① 只把射程除以 spacing 却没归一化距离 → `distanceFactor` 归零，症状「政体 4 个、控制率 1.6%」。**两边必须同时换算。** ② 射程改对了但评分公式的假参数还在（见下）。

**本轮最重要的修正：内陆环状空心（又一个「自检全绿但图不对」的案例）**

自检 13 条全过、数字合理（政体 12、控制率 58.7%、走廊 175 块、枢纽联通 100%），
但预览图上**大块内陆深灰未声明，领土沿海南与河流成环**。

这次没先调参，而是**先造诊断**（`DiagCivilization`）。诊断先**排除**了错误假设（怀疑地形惩罚过重，实测阻尼只有 0.58~0.77，不足以解释），
再做**判定实验**：按同一公式重算但把 `distanceFactor` 强行置 1 →「高原（高程>0.70）163 块，越阈值仅 15 块（9.2%）」。
**证明瓶颈与距离无关，而是乘性链天花板本身低于阈值**：

```
score = localSupport × terrainDamp × distanceFactor × ...
```

每个因子单看温和（0.58 / 0.77 / 0.86），相乘后整体跌破 0.2588。这是**乘积陷阱**，且性质恶劣：**任何单项调参都救不回来**。（若不做这个实验，会在"调射程"和"调地形惩罚"之间反复试错。）

**真正的根因四个，逐个修掉**

| 问题 | 性质 |
|---|---|
| 海拔被惩罚两次：`terrainAdaptation`（内含地形项）与 `1 - terrainPenalty*0.42` 同时挂乘性链 | 乘积陷阱 |
| `terrainStability = 1 - heightFromSea^1.25` 把"高"等同于"不宜居" | 判据本身错了 |
| `localSupport = potential*0.72 + riverFactor*0.28` 让无河内陆潜力被打七折 | 继承栅格版的偏置 |
| 兜底撒点门槛固定 `potential >= 0.62`，高原潜力只有 0.21~0.30 → **高原永远播不下种子** | 死条件 |

修法：① 海拔只经 `terrainAdaptation` 惩罚一次；② 新增 `ComputeRuggedness`——稳定性改看**局部起伏**（相邻地块平均高差，标尺 0.18）而非绝对海拔，**这是地块模型才有的能力**（栅格 8 邻域斜对角距离 √2 倍，高差不能直接平均）；③ `potential` 系数 0.72 → 0.88，河流留 0.12 作纯加成 + 乘性 `1+rf*0.10`；④ 播种门槛随海拔放宽 `0.62 → 0.62 - altitudeT*0.32`。

**效果（573 陆地块）**：内陆平均影响力 0.2212 → **0.4922**；沿海声明率 71.9% → 97.3%；内陆 34.4% → 79.3%；控制率 48.9% → 86.2%；**影响力为 0 的地块 77 → 0**。预览图环形空心彻底消失，只剩海拔 >0.7 的极陡山脊留深灰（合理的"不宜居山脊"）。

**顺带抓到的两个回归**

1. **距离衰减矫枉过正**：第一版把 `d<=R` 的平台期给成常量 1.0 → 射程内完全不衰减，强政体一路碾压，政体数 14 → **8**、单块领土吃掉整个大陆。改成"平台期 0.82~1.0 线性缓降 + 尾部幂次衰减"后回到 10 个。**"让内陆可填充"和"保留政体竞争"是同一式子上必须同时满足的两个要求。**
2. **零领土政体破坏编号不变量**：出现"某弱种子一个地块都没抢到" → `polityIdMap` 出现编号 ≥ `PolityCount`，自检「政体编号在范围内」报错。**第一版修法方向错了**：在评分阶段给发祥地加 `BirthplaceHoldBonus`——它只把归属与纪元两阶段强行对齐，纪元动态仍能造出零领土政体，且保底让本该被吞并的政体活下来，**破坏了"纪元推进→政体数不增"的单调性**（自检报"12/13/13 出现反弹"）。正确修法是把不变量做在**出口处**：所有改归属的环节跑完后统一 `RenumberPolities`（剔除零领土、编号压紧 0..N-1）。**不变量由结构保证，不靠各环节自觉。**

**实测**：自检全部通过（含 1g 生态、1h 文明 15 条）；类型检查 0 错误 / 45 警告（与基线一致）；预览图 6 个裸 RGBA 已核对。

**P4 之后剩余**：`Wind` 是栅格侧最后一个图层；增量重绘的解锁条件（三图层数据源地块化）已具备但尚未实施；`Cities` 因需地形总览做背景，仍是"半连续 + 标记"的混合图层。

## 环境事实（重要，避免重复踩坑）

- **本机非交互 shell 里 NuGet 彻底不可用**：`dotnet nuget locals all --list` 单独执行也报 `Value cannot be null. (Parameter 'path1')`（`APPDATA` 不在 shell 环境里；补 APPDATA/LOCALAPPDATA/USERPROFILE/NUGET_PACKAGES 均**无效**——NuGet 走 Win32 API 而不是环境变量；PowerShell 工具调用外部程序会被安全策略静默拦截）。后果：`dotnet build PlanetGeneration.csproj` → `无法解析 SDK "Godot.NET.Sdk"`；任何带包依赖的工程都无法还原。
- **该环境问题会传递给子进程**：从本会话启动 Godot 执行 `--headless --build-solutions`，报的是**同一个** `无法解析 SDK "Godot.NET.Sdk"`（`dotnet_build_project` 步骤显示 DONE 但回调失败）。补 `APPDATA` 能修好 Godot 的 `Could not open 'user://'`，但修不好 NuGet。**结论：任何从这个会话发起的 Godot 构建都不可用**，只能靠 `tools/godot-typecheck` 做类型检查，或让用户在自己的编辑器里构建。
- **绕行办法（已验证可用）**：在自检工程里用**显式 `Import Sdk.props / Sdk.targets`**，并在其后把 `ResolvePackageAssets`、`ResolvePackageDependenciesForBuild`、`GenerateBuildDependencyFile`、`GenerateBuildRuntimeConfigurationFiles` 覆盖成**空目标**，再手工提供 `.runtimeconfig.json`（用 `<None Update>` + `CopyToOutputDirectory` 复制）。命令：`dotnet build X.csproj --no-restore -p:RestoreProjectStyle=None`。
  - 注意：`Directory.Build.targets` 里定义同名空目标**无效**（导入顺序在 SDK 目标之前）；必须用显式 Import 写在 `Sdk.targets` 之后。
  - XML 注释里不能出现 `--`（例如 `--no-restore`），否则 MSB4024。
  - 直接调用 Roslyn 编译器会被安全策略拦截（"csc.exe compiles arbitrary C# code"）。
- **Godot 工程的类型检查做法（已验证）**：新建 csproj，`EnableDefaultCompileItems=false` + `<Compile Include="..\..\csharp\scripts\**\*.cs" />`，用 `<Reference><HintPath>` 指向 `~/.nuget/packages/godotsharp/4.7.2/lib/net8.0/GodotSharp.dll`、`llamasharp/0.25.0/lib/net8.0/LLamaSharp.dll`、`microsoft.extensions.logging.abstractions/9.0.8/lib/net9.0/*.dll`。不需要 Godot 源生成器（工程里只有 `SceneTree.SignalName`，那是 GodotSharp 自带的）。
- 自检工程放在 `procgenesis_local/tools/polygon-selftest/`（`csharp/` **之外**）：Godot 工程目录下再放一个 `.csproj` 会让 `dotnet build` 报 MSB1011（多个工程文件）。
- 工程目录下有多个项目/解决方案文件（`PlanetGeneration.csproj`、`PlanetGeneration.csproj.old`、`csharp.sln`），裸 `dotnet build` 会报 MSB1011，必须指定 csproj。
- Godot 4.7.2 mono 编辑器：`D:\Program Files\Godot_v4.7.2-stable_mono_win64\`（经 `~/bin/godot` 脚本调用）。
- 本项目 `dotnet` 可用版本 10.0.401（工程 target net8.0；运行时 8.0.31 / 9.0.20 / 10.0.12 都在）。
- `Math.Clamp(value, min, max)` 在 `min > max` 时**抛异常**——极小地图的 `MinCellsDesired` 上限必须让位。
- C# 不允许 `out` 参数跟在可选参数之后（CS1737）。
