# 重构实施记录 — 2026-09-23

## 范围与原则

本轮基于已有未提交工作继续推进，没有回滚制图、纹理、Map Effects、DecoupledRelief 等既有改动，也没有创建 Git 提交。

优先清除重复算法与不清晰的数据边界，并对代码搬移建立可执行基线。不是将全部原始行为无条件冻结：下面单独列出的缓存、河网、拾取与制图副作用问题属于有意修正。

## 已落地

### 1. 缓存身份与旧档案兼容

- `GenerationOptions.BuildCacheKey()` 委托 `WorldGenerationCacheKey`，Main 不再独立拼接生成参数。
- 缓存格式版本与算法版本分开；补齐风场、微调预设全部值和有效地貌参数。
- 使用 invariant round-trip 浮点格式与文本转义，避免区域设置、浮点取整和分隔符引发碰撞。
- 修正 Main 接收 tuning 参数却未写入 GenerationOptions 的遗漏。
- `WorldArchiveHeader` 支持旧 `ver:...|宽x高|seed:...` 与新的 `ext:/seed:`，只读取大档案前部。
- 算法版本更新为 8，使旧自动缓存自然失效；不删除用户磁盘缓存或手动档案。

### 2. 旧 Polygon 实现收敛

旧目录从 Git 基线的 5500 物理行收敛到约 736 行。删除重复的 Voronoi、数学向量、字段模型；其余入口转为调用 Core：

- `PolygonGrid` 仅组合 `CellGeometry` / `CellFields`，通过引用共享数组。
- 构建、校验、像素归属、颜色填充、下游拓扑、连通分量、地貌、生态、文明和河流复用 Core。
- 旧 API 的 32768 默认档位、小地图像素上限、默认直接使用湿度的 BuildFlux 语义继续保留。
- 旧像素四邻域描边保持原外观，不强行替换为 Core 的几何线段描边。
- `RasterPolygonBridge` 与少量旧调用辅助逻辑保留，不把“兼容层仍存在”说成“旧栅格路径已经删除”。
- 模拟结果与事件直接使用 Core 类型；栅格生态的群系生产力表也统一到 Core。
- `PolygonTileMode` 移入 UI.State，持久化枚举编号保持 0/1/2/3。

### 3. 数据隔离与状态归属

- `CartographyGenerator.Generate` 在入口克隆艺术工作字段。蓝图和画师不再写回已经用于物理、生态、文明和统计的字段。
- 这是明确的职责修正：开启纯制图蓝图不再改写物理世界；制图笔刷仍消费蓝图工作场。
- `WorldSnapshot` 文档明确“只读契约”不等于数组已经类型级不可变，避免虚假安全保证。
- 将 `GeneratedWorldData` / `LayerRenderCacheEntry` 移出 Main.State 到 Application；模拟失效规则由数据拥有者集中维护。
- 渲染归属缓存以几何实例与分辨率为身份，不再只比较地块数；板块线缓存同时检查字段实例。

### 4. 大文件按职责拆分

- `WorldPlanner.cs` 从 1386 行降为 68 行，只保留阶段编排。
- 内部模块：ContinentLayoutPlanner、MountainLayoutPlanner、RiverLayoutPlanner、BiomeRegionPlanner、SettlementLayoutPlanner、InfrastructurePlanner、PlanningGeometry。
- 搬移前记录规划结果/字段指纹，搬移后完全一致。
- `GuohuaMapRenderer.cs` 从 2979 行降为 2397 行，11 个备用纹理生成方法及其局部配色移到 `GuohuaFallbackTextures`。
- 11 个备用纹理搬移前后的 RGBA 像素指纹完全一致。
- 资源目录共同使用 `AssetTextLoader`；保留备用路径，报告读取异常，修复空资源提前终止备用读取的问题。

### 5. LLM 生命周期

- 四类请求共用 BeginInferenceOperation / CompleteInferenceOperation。
- 每个请求持有自己的 CancellationTokenSource，由自己的 finally 释放。
- 被新请求替换的旧请求不能把新请求的推理状态改为空闲。
- await 后检查请求取消状态，再发布输出；不以底层返回的取消字符串冒充正常成功。
- 此轮未修改模型选择、采样策略或提示词，不声称已验证真实模型推理。

### 6. 测试开发体验

- 原有 16 项测试完整保留并迁入领域分组文件。
- 新增缓存字段覆盖、档案兼容、几何适配、模拟逐字段一致、快照隔离和规划指纹测试。
- 支持 --quick / --full / --suite / --list，空分组返回非零，逐项记录耗时。

## 续篇：单一生成路径与完整快照持久化

本轮继续推进，而不是再次只调整文件结构。

### 当前数据流

```text
捕获 GenerationOptions（A 与可选 B）
  → SnapshotGenerationController
  → 每组一次 WorldGenerationService.GenerateAsync
  → WorldSnapshot
  → SnapshotWorldProjection（旧界面的栅格/城市/模拟数据）
  → Main 渲染、叙事、导出

WorldSnapshot → WorldSnapshotArchive → 磁盘
磁盘 → 完整 WorldSnapshot + 重建空间索引 → 独立旧界面投影
```

### 已完成

- 删除 Main.Generation.Driver 的独立 `BuildWorldAsync` 栅格生成管线及对应生成器字段。
- `SnapshotGenerationController` 负责生成和投影，只有两组都成功才返回可发布的结果。预取消请求不会进入基础场生成。
- `SnapshotWorldProjection` 单向构建旧界面所需的高程、温湿度、风、水文、群系、矿产、城市、生态和文明数据；不重新生成世界。
- `_primarySnapshot` / `_compareSnapshot` 从活动世界的 Snapshot 派生，不再维护第二套可独立赋值的引用。
- 输入在第一次 await 前捕获；会话缓存键纳入 A/B 两组完整输入，B 组确实使用 Seed + 1 和自身预设。
- 正常世界的模拟消费者不再调用旧栅格模拟器；时间轴使用 Core 模拟并发布新快照，再更新旧界面投影。
- 兼容网格使用独立字段副本，旧交互不能通过网格数组写回快照。
- 内存缓存只保留快照，命中时创建独立活动投影。活动会话推进纪元不会污染原缓存条目。
- 磁盘自动缓存及新手动档案保存完整快照，包含几何、所有 CellFields 列、实体、统计、模拟、连续风场、宏观区域、制图命令与道路。
- 重载时创建新运行时 ID 并重建空间索引，避免误用上一份渲染缓存；保留原创建时间。
- 使用同目录临时文件与原子替换，保存失败不会覆盖旧文件；自动缓存的读取/写入失败记录上下文。
- 旧手动 JSON 档案继续走原有导入/重存路径；不自动伪造缺失的快照，也不作为新生成路径的自动缓存。
- 新档案载入后恢复生成参数、预设、纪元与蓝图选择；UI 更新不触发参数变更事件。
- 算法版本提升到 **9**，旧自动缓存自然失效，不删除用户档案。
- 缓存面板显示可计数的基础数组缓冲，明确不含制图和对象开销，不再套用栅格每像素估值。

### 当前仍保留的边界与限制

1. `GeneratedWorldData` 仍存在，但对新生成世界仅是衍生投影；旧手动档案缺失快照时仍允许旧路径运行。

4. PlateResult 的旧压力图、边界点/邻居中间结构不在权威快照中，投影不重新计算这些生成期中间结果；新 Core 渲染使用快照场与几何。

6. Main 的控件接线、旧档案导入和部分渲染编排尚未整体迁出；快照数组也仍靠只读契约保护。
7. Godot 回归覆盖真实生成和调用边界，但不是整套 Main 场景交互录像，也不替代完整国画视觉检查和真实 LLM 模型推理。
