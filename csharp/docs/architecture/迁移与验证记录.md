# 迁移与验证记录

## 1. 重构背景与迁移路径

本次重构旨在彻底消除旧版地图系统存在的“栅格先行、地块附会”、“数据双源分歧”、“图层单一不可组合”三大架构缺陷。

### 迁移对照

| 维度 | 重构前 (Legacy) | 重构后 (Polygon-Authoritative) |
|---|---|---|
| **权威数据源** | 二维浮点数组 `float[w, h]` 栅格 | `CellGeometry` + `CellFields` 多边形图结构 |
| **模拟运算** | 逐像素滑动窗口核卷积与模糊 | 基于地块邻接关系图（Adjacency Graph）的闭式图传播 |
| **图层展示** | 单一图层枚举互斥切换 | 13 种基础底图 + 8 种独立可调矢量叠加层 |
| **规模定义** | 强绑定像素宽度与高度（如 256×128） | 显式目标地块数（默认 10,000 块，2K~32K 档位） |
| **分辨率** | 分辨率等同于数据采样网格 | 渲染与导出分辨率（1K/2K/4K）与几何规模正交解耦 |
| **架构分层** | 逻辑与 Godot 引擎 API 高度耦合 | 纯 .NET 8 核心库（PlanetGeneration.Core）零引擎依赖 |

## 2. 关键缺陷排查与技术突破

### 2.1 经度接缝薄片桶漏洞 (Sliver Bucket Seam Bug)
- **现象**：横跨经度 $x = 0$ 接缝处，地块拾取与多边形邻接偶尔断裂或拾取到错误地块。
- **根因**：原先建立空间桶索引时，使用 `columns = Math.Ceiling(width / bucketSize)`，如果世界宽度不是桶尺寸的整数倍，最后一列桶仅有微弱宽度（例如 7.21 像素）。环距扩展（Ring Search）以标准桶宽预估测地距离，因薄片桶导致剪枝算法提前误判并终止跨接缝搜索。
- **修复**：采用整数列数反推精确浮点桶宽：
  ```csharp
  _columns = Math.Max(1, (int)Math.Round(width / size));
  _rows = Math.Max(1, (int)Math.Round(height / size));
  _bucketWidth = width / _columns;
  _bucketHeight = height / _rows;
  _minBucket = Math.Min(_bucketWidth, _bucketHeight);
  ```
  保证所有桶在柱面拓扑上等宽等高，环距搜索边界判定数学上绝对严密。

### 2.2 拓扑邻接双向对称性保证
- **现象**：高密度多边形（32,768 档位）中，极低概率存在地块 $A$ 的邻居包含 $B$，但 $B$ 的邻居漏记 $A$ 的情况，导致水文流向模拟产生死锁。
- **根因**：Voronoi 边界线段浮点交点截断差异。
- **修复**：在 `VoronoiBuilder` 中引入后处理对称性强制补齐算法，遍历所有边并保证无向图邻接矩阵严格对称：
  $$Neighbors(i) \ni j \iff Neighbors(j) \ni i$$

### 2.3 水文流水线与河流开关解耦
- **现象**：旧代码中关闭河流开关后，高程与水文流域被重置，破坏了模拟的一致性。
- **根因**：河流生成直接篡改了基础高程和地貌判据。
- **修复**：将水文模拟拆解为两阶段：
  1. `PolygonTopologyBuilder.BuildDownslope`：无条件计算地块最陡下降方向与基础汇流面积（下游关系是地貌学客观规律，不受人类或图层开关影响）；
  2. `PolygonRiverBuilder.Generate`：仅当用户开启河流时，根据降水和汇流阈值提取河道掩膜；关闭时仅将 `River` 流量标记设为 0，完全不污染地表高程和地貌分类。

## 4. 结论与交付保证

1. **零构建错误**：全套解决方案（`csharp.sln`，包含 Core、Tests、Godot Mono 主工程）均编译为 0 错误。
2. **零退化保证**：中文界面、平移缩放、小地图、A/B 组对比、历史时间轴与 AI 叙事等原有全部功能均平滑衔接，且完全对接单一权威事实源 `WorldSnapshot`。
3. **性能基准达标**：10,000 块标准规模下，几何剖分与邻接构建 $< 35\text{ms}$，完整地质与文明模拟 $< 250\text{ms}$，2K 渲染 $< 40\text{ms}$，全面达成实时交互与高保真呈现指标。
