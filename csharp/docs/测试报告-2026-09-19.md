## 2. 已修复问题

### BUG-1（致命）随机种子完全失效，所有新世界种子恒为 0
- **复现**：启动游戏 → 新建世界 → 反复点击 d20"随机世界种子"→ 种子始终显示 0；生成后磁盘缓存 `cache_key` 恒为 `seed:0`。
- **影响**：任意次数生成同一张地图，"随机世界"核心玩法失效；历史存档/缓存全部 `seed:0`。
- **根因**：UI 重构时控制台"地貌参数"页（含允许负种子的 SeedSpin）被移除，`GeneratorControlsController.HasParamControls=false`，`Main._seedSpin` 经 `GetNodeByName` 回退绑定到**创世工坊**的 SeedSpin；该 SpinBox 未设 `min_value`（默认 0），而 `SetRandomSeed()` 在完整 int 范围取值（约一半为负）→ 负种子被 Range 钳制为 0。
- **修复**：
  - `scenes/WorldSetupMenu.tscn`：SeedSpin 增加 `min_value = -2147483600.0`（与旧参数页一致）；
  - `WorldSetupController` 新增 `SetSeed()`，`Main.OnWorldSetupRandom` 随机后显式回写工坊界面，保证显示/存档名/实际生成三者一致。
- **回归**：d20 后显示随机负种子（实测 `-573324018`）；生成后缓存 `seed:-871334039` 与工坊界面显示完全一致。✅

### BUG-2（严重）主菜单"读取档案"是死按钮，点击后进入无 UI 死胡同
- **复现**：主菜单 → 读取档案 → 菜单关闭，画面全空白；无世界时控制台/召唤把手全部隐藏，无法返回主菜单，只能重启。
- **影响**：核心入口不可用；新玩家误触后必然卡死。
- **根因**：`MainMenu.cs` 中 `%LoadButton.Pressed += Close` 只关菜单，未接任何加载逻辑。
- **修复**：`MainMenu` 新增 `LoadRequested` 事件；`Main` 新增 `OnLoadFromMenuRequested`——优先读 `_lastArchivePath`，否则取存档目录最新一份，加载成功进入控制台；无可用存档或读取失败时回退到"新建世界"流程，保证任何情况下都有出路。
- **回归**：主菜单点"读取档案"→ 自动载入最新存档并进入观测台，可继续操作。✅

### BUG-3（严重）会话内读档后画面仍是旧世界
- **复现**：生成一个世界 → 观察法则 → 选择存档读取 → 画面/悬停信息仍为上一次生成的世界。
- **影响**：读档功能给出错误数据，玩家以为存档损坏。
- **根因**：`RedrawCurrentLayer` 在 `_primarySnapshot != null` 时完全以核心库快照为渲染源，而 `LoadArchiveByPath` 只恢复栅格 `_primaryWorld`、不清空旧快照；`MapCanvas` 也继续持有旧快照供悬停拾取。
- **修复**：`LoadArchiveByPath` 中置空 `_primarySnapshot/_compareSnapshot` 并调用新增的 `MapCanvas.DetachSnapshot()`（清空网格/缓存边并重绘），使渲染走存档栅格路径。
- **回归**：读档后渲染与信息标签切换为存档内容，无异常日志。✅
- **备注**：存档只含栅格数据，读档后画面走旧栅格管线，与生成时展示的核心库快照"同 seed 两种画面"（见遗留风险 R1）。

### BUG-4（严重）磁盘自动缓存无限增长
- **复现**：多次生成后观察 `user://cache/world_cache/`：实测积累 **480 个文件 / 11.28 GB**，只写不删。
- **影响**：磁盘空间持续泄漏；档案列表刷新等操作扫描变慢。
- **根因**：内存缓存有 LRU 淘汰（6 条），磁盘缓存写入后从不清理。
- **修复**：`SaveWorldGenerationCacheToDisk` 写入后按最旧优先修剪，保留最新 `WorldCacheDiskKeepFiles=24` 份（单个文件删除失败时跳过，下次再试）。
- **回归**：一次生成后磁盘缓存从 480 → **24 个文件（3.82 GB）**，观测台统计同步。✅

### BUG-5（严重·性能）湿度扩散占总生成时长 60%
- **复现**：默认 2K 生成，日志 `湿度扩散: 30526 ms`（总 54.3s）。单线程逐海洋格沿风场路径步进（每格上限 1000 步，亿级步数）。
- **影响**：高配机 30s+，低配机分钟级；4K 地图不可用。
- **修复**：`MoistureGenerator.DistributeMoisture` 主循环改为**按行分带并行 + 每带私有全图缓冲 + 固定顺序合并**：带内保持与原实现一致的串行顺序，带间按下标合并，因此**同种子同参数结果逐位确定**；缓冲总内存以 96MB 封顶（4K 时自动降带数），单核/超限时回退原串行路径。
- **回归**：`湿度扩散: 15109 ms`（**30.5s → 15.1s，2×提速**），总生成 54.3s → 33.1s；SelfTest 8/8 通过。
- **说明**：与旧单线程结果存在微小数值差异（并发改变了路径回读的可见时序），但运行间确定性保持；群系整体分布一致。

### BUG-6（一般）保存存档冻结主线程 + 档案下拉每次全量解析所有存档
- **复现**：点击"保存存档"→ UI 冻结数秒（单份存档 JSON 约 185MB）；`SetupArchiveOptions` 为每个存档标签做整档 `Json.Parse`（10 份 × ~60-185MB）。
- **根因**：序列化+写盘在主线程；标签构建复用了整档解析。
- **修复**：
  - 保存移入 `Task.Run`（`SaveArchiveAsync`，带 `_isSavingArchive` 防重入），完成后借 Godot 主线程同步上下文刷新 UI；
  - 新增 `TryReadPersistedCacheHeaderFromFile` 只读头部 4KB，从 `cache_key`（`ver:N|宽x高|seed:S`，字母序位于文件最前）与 `compare_mode` 解析标签——注意 `Json.Stringify` 按键名字母序输出，`seed` 字段本体排在数 MB 的 `primary` 之后，必须走 cache_key。
- **回归**：保存期间 UI 保持响应；新档立即出现在下拉且标签格式正确（`09-19 01:12 | seed:0 | 2048x1024 | 单图`）。✅

### BUG-7（轻微）叙事推演页子标签外露内部节点名
- **复现**：控制台 → 叙事推演 → 子标签显示 "LoreTab / OracleTab"。
- **根因**：场景用 `metadata/_tab_title` 存了中文标题（"区域详情"/"AI 推演"），但没有任何代码套用到该 TabContainer。
- **修复**：`Main.Oracle.InitializeOracleUI` 按 `_tab_title` 元数据设置标签标题（与主控制台同一约定）。
- **回归**：显示"区域详情 / AI 推演"。✅

## 3. 遗留风险与后续优化建议

**R1（架构，中）同 seed 双管线画面不一致**：生成时展示核心库 `WorldSnapshot`（多边形权威源），读档只有栅格数据走旧管线渲染，同一 seed 两画面差异明显。迁移完成后应让存档携带（或读档时按参数重建）核心库快照，统一渲染源。

**R2（性能，中）湿度扩散仍有 15s**：2× 并行加速后仍是最大热点（内存带宽型随机访问）。进一步优化需改变访存模式（如按风场分区的波前推进）或降步数上限，会改变输出模式，建议在多边形管线彻底接管后再处理。

**R3（数据体积，中）单份存档/缓存 185MB+ JSON**：栅格数组以 JSON 文本存储。建议后续改二进制（`Image`/`Flatten` + `FileAccess` 或 MessagePack），体积与读写时间可降 1-2 个数量级；磁盘缓存保留 24 份在 4K 地图下仍可达 ~4GB，可考虑改为"数量+总字节"双预算。

**R4（健壮性，低）生成异常静默**：`GenerateWorldAsync` 只有 `finally` 没有 `catch`，生成抛异常时用户得不到任何提示（进度条消失但无错误信息）。建议补 catch → 信息栏/对话框提示。

**R5（接线卫生，低）d20 双重绑定**：创世工坊 d20 同时被 `WorldSetupController`（RandomRequested）与 `Main._randomButton` 回退绑定接两次，每次点击产生两个随机数（显示/使用最终值一致，无用户可见影响）。整理 `_seedSpin/_randomButton` 的回退绑定链可消除。

**R6（UI 一致性，低）观测台地块数口径**：观测台显示核心快照地块数（目标 10,000 · 实际 10,011），而渲染的多边形地块层为旧管线 32,768 块（`cells_desired` 独立配置），两套"地块"并存易混淆，属 R1 的一部分。

**R7（音效）**：项目当前没有任何音频资源与播放逻辑，属未实现功能而非缺陷，可按需补 BGM/交互音。

**R8（并行工作区提醒）**：本次会话期间 Godot 编辑器处于打开状态，工作区中存在并行产生的未提交改动（`resources/textures/world_setup/*` 贴图更新、`WorldSetupMenu.tscn` 样式参数、未跟踪的 `CaptureWorldSetup*.gd` 截图脚本与渲染 PNG）。这些不是本次修复的内容，已原样保留；**若在编辑器中回存 `WorldSetupMenu.tscn`，请注意保留第 362 行 `min_value = -2147483600.0`**。
